# 시스템 테이블 경계 이상 감사 — 번역 배치 0003–0004

## 범위 및 번역 정책

- 대상: 승인 `batch_0003.jsonl`, `batch_0004.jsonl`에 속한 `unmatched_system_units` 80건
- 번역·축약 판단: **Codex 내부 모델만 사용**
- 외부 번역 모델/API: **사용하지 않음**
- 기존 reviewed 배치와 `translation_memory_draft.json`: **수정하지 않음**
- 전체 기계 판독 결과: `batches_0003_0004.json`

## 엄격한 연결 절차

1. 각 TM의 모든 `occurrence_id`를 `work/catalog/text_v2/text_catalog.json`에서 역참조했다.
2. NUL 스캐너 범위 `[offset, offset + byte_length)`와 같은 스키마의 구조화 table unit 원문 바이트 범위를 비교했다.
3. 범위가 **정확히 한 table unit과 겹칠 때만** 연결했다. `substring_candidates`는 참고만 했으며 확정 근거로 쓰지 않았다.
4. scanner raw slice와 table field raw slice를 카탈로그가 지목한 원시 payload에서 다시 읽었다.
5. 원시 payload 전체 SHA-256도 각 table catalog의 `source_sha256`과 다시 대조했다.
6. 정리된 한국어를 현행 `canonical_v1/codebook.json`으로 인코딩하고, NUL 종단 1바이트를 예약한 `capacity - 1` 한계와 비교했다.

## 구조 접두부 혼입의 대표 증거

- `help:340:title`: scanner `0x1CCD8`, 실제 필드 `0x1CCDC`; `0F6A7C20`이 `<$0F>j| `로 잘못 붙었다.
- `help:252:title`: scanner `0x15590`, 실제 필드 `0x15594`; `10091420`이 `<$10>\t<$14> `로 잘못 붙었다.
- `chat:187:title`: scanner `0x76CA`, 실제 필드 `0x76CC`; `011F`가 `<$01><$1F>`로 잘못 붙었다.
- `magic:31:menu_name`: scanner `0x13DB`, 실제 필드 `0x13DC`; `38`이 `8`로 잘못 붙었다.
- `special:67:name`: scanner `0x25AF`, 실제 필드 `0x25B0`; `5A`가 `Z`로 잘못 붙었다.

80건 각각의 scanner/table offset, raw hex, offset 차이, 겹친 바이트 수, payload 경로 및 SHA-256 검증 결과는 JSON의 `evidence`에 기록했다.

## 별도 조치 목록

### Ambiguous / unmatched

- 없음.
- 향후 발생 시 substring 유사도만으로 확정하지 말고, 구조 스키마 또는 원시 offset 증거를 추가 확보할 때까지 삽입 대상에서 제외한다.

### Overflow

- 없음. 80건 모두 NUL 1바이트를 포함해 각 필드 capacity 안에 들어간다.
- 향후 고정 필드 overflow 발생 시 의미 보존 축약안을 재승인하거나, 별도로 왕복 검증된 resizable 경로만 사용한다.

### 인코딩 오류

- 없음. 80건 모두 현행 canonical codebook으로 인코딩되었다.
- 향후 누락 글자가 생기면 canonical codebook을 확장하고 글꼴 아틀라스를 다시 렌더링한 뒤 재검증한다.
